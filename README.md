# СтройБаза

Строительный интернет-магазин на React и Vite.

## Запуск

```powershell
npm ci
npm run dev
```

Для проверки итоговой сборки выполните `npm run build`, затем `npm run preview`.
Папка `dist` содержит статическую сборку. Маршруты после `#` работают и на статическом хостинге.
https://feterm.github.io/kr1-html-css-shop/

## GitHub Pages

В настройках репозитория откройте **Settings → Pages → Build and deployment** и выберите **GitHub Actions** в поле **Source**. При пуше в `main` workflow установит зависимости, соберёт проект и опубликует папку `dist`. Результат доступен во вкладке **Actions**.


## Возможности

- Каталог с категориями, поиском, фильтрами по цене и наличию и сортировкой.
- Карточки товаров с характеристиками и отзывами, избранное, сравнение до трёх позиций и последние четыре просмотра.
- Корзина, проверка наличия, расчёт доставки, выбор даты и интервала получения, история заказов в личном кабинете.
- Общий поиск по каталогу, страницам и услугам, светлая и тёмная темы.
- Чат с автоответчиком по товарам, остаткам, самовывозу и доставке.

Магазин работает без сервера. Корзина, заказы, отзывы, избранное, история просмотров и чата хранятся в браузере. Остатки меняются после оформления заказа в этом же браузере. Чат отвечает по данным каталога, подключение к оператору не настроено. Платежи не проводятся.


Дополнительно доступны график выдачи и доставки на неделю, резерв товара, услуги с заявками и отзывами, локальная регистрация и редактирование профиля, форма сохранения адреса для спецпредложений и встроенная карта Яндекса. На главной есть десять примеров отзывов, помеченных как примеры, и отзывы, добавленные в браузере. Телефон, почта и адрес используются в качестве примера. Рассылки и серверная обработка заявок не подключены.

## Задания с фотографий — практические №13–15

Выполнены выделенные пункты.

- JavaScript: объект товара содержит строки, числа, логическое наличие и процент скидки. В src/product-functions.js реализованы formatPrice, calculateDiscount, calculateFinalPrice, getProductStatus и createProductSummary. Форматирование и статус используются в карточках, описание — на странице товара. При загрузке сайта src/practice-console.js печатает объект и результаты функций в консоль.
- Доступность: у изображений есть alt. Удалена лишняя ARIA-подпись логотипа, которая расходилась с видимым текстом. Размер переключателей отзывов увеличен. Проверены подписи кнопок, состояние переключателей и нативные поля форм.
- Адаптивные изображения: public/store-assets/responsive содержит WebP-варианты товаров 240/480 px и баннера 768/1280/1942 px. Товары используют srcset/sizes, баннер — media query и image-set.
- Проверены ширины 360, 430, 768, 1024 и 1440 px. Формы и сравнение проверяются с непустой корзиной и выбранными товарами.
- Lighthouse Accessibility: главная, каталог, оформление и сравнение проверены в светлой и тёмной темах. Отчёты HTML и JSON сохранены в lighthouse/. Итоговый результат каждого из восьми отчётов — 100/100. Это автоматический аудит, ручная проверка клавиатуры описана ниже.
- Клавиатура: ссылка пропуска переводит фокус в main, диалог поиска закрывается по Escape с возвратом фокуса. Широкая таблица прокручивается внутри своего контейнера.

React выводит строки как текст. В карточке используется createProductSummary без вставки через innerHTML. Функции проверяют некорректные цены и проценты, а округление расчёта выполняется до копеек.

## Сервер расчётов на Go

В backend/ находится HTTP-сервер на стандартной библиотеке Go, без сторонних пакетов. Требуется Go 1.22 или новее.

API принимает POST /api/calculate с JSON:

    {"name":"Дрель","price":7990,"discountPercent":10,"stock":3,"isAvailable":true}

Ответ содержит formattedPrice, discount, finalPrice, status и summary. Проверяются диапазоны чисел, пустое название, неизвестные поля, размер и структура JSON. GET /api/health проверяет доступность сервера.

Сервер выполняет арифметику и форматирование введённых параметров. Это калькулятор, он не является серверной проверкой заказа, авторизацией или базой товарных остатков.

Чтобы собрать React с подключением API и запустить его через Go, выполните из корня проекта в PowerShell:

    $env:VITE_API_URL = "/api"
    npm run build
    Remove-Item Env:VITE_API_URL
    cd backend
    go test ./...
    go run .

Откройте http://127.0.0.1:8080/. В карточке товара браузер запрашивает Go API и показывает серверный summary. При ошибке сети выводится сообщение, локальное описание остаётся доступно.

Для разработки обычной статической версии используйте npm run dev. Сборка без VITE_API_URL работает на GitHub Pages. GitHub Pages публикует только фронтенд, для Go нужен отдельный сервер.

Отдельные репозитории kr3-responsive-shop и kr4-js-shop не создавались: по ранее принятому указанию работа продолжается в kr1-html-css-shop.
